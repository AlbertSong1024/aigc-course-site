# 项目现状评估与「智慧课程 / 教学智能体大赛」申报补强建议

> 评估对象：`tutorial-site` AIGC应用与实践 · 课程教程站
> 评估时间：2026-09-27 ｜ 当前版本：v1.0，已上线 32 / 32 课
> 校验状态：`tools/check_site.js` **通过 665 · 警告 0 · 失败 0**

---

## 一、先给结论

**这个项目在「教学工具」维度已经很强，但在「申报材料」维度还很薄。**

原因很简单：你做的是一套**自用型教学基础设施**——纯静态、零依赖、断网可用、离线优先。
它的技术含金量和教学实用性都够，甚至超过很多申报项目。但它**刻意回避了当前主流智慧课程
评价体系最看重的几样东西**：云端学习行为数据、学习者画像、成绩/证书体系、师生在线交互。

所以申报要补的不是「再做功能」，而是**在守住离线底线的同时，开一条可选的线上数据通路**，
以及**把现有能力翻译成评委看得懂的证据材料**。

下面按「已有 → 缺口 → 补法」三层说。

## 三、申报的核心缺口（按严重程度排序）

### 🔴 P0 — 学习行为数据没有云端通路，这是最大短板

**现状**：所有学情数据在 `localStorage`，靠学生「导出 JSON → 交给老师」。
老师拿到的是**离散快照**，不是连续数据流。

**为什么是致命伤**：智慧课程认定、教学能力比赛、智能体大赛，几乎都要求
「**基于学习行为数据的精准教学**」「**学习画像**」「**数据驱动**」。
离散导入的 JSON 撑不起「实时学情」这个叙事——评委一问「数据怎么采集的、
多久更新一次」，答「学生手动导出」就掉档。

**补法（推荐 Umami 作为第一步，已内置）**：
1. 启用已写好的 `analytics.js`（填网站 ID 即可，无需改代码）；
2. **更强的一步：把 `lt_endpoint_v1` 用起来**——`learning-tracker.js` 早就支持
   匿名上报到自建端点，只是没接。搭一个最小后端（腾讯云函数 / 云托管几十行代码）
   接收 `{sid, name, at, summary}`，就能把离散快照变成**连续数据流**：
   - 学生每次离开页面自动上报；
   - 老师看板不再需要学生交档案，直接读云端汇总；
   - 可以画「班级完课率随时间变化」「某课的退出点分布」——**这才是评委要的曲线**。

> ⚠️ 接云端会打破「零依赖/断网可用」原则。**正确做法：离线仍是底座，云端是可选增强层。**
> 断网时功能全部照常，联网时数据自动汇聚。这个「双模架构」本身就是申报亮点。

### 🔴 P0 — 没有「学习成果 / 评价」闭环

**现状**：有 54 处随堂自测，但都是**看完答案**式自评，不记分、不汇总、不发证。

**缺什么**：智慧课程认定要求学生「学习成效可测量」。目前只有过程数据（停留、完成度），
没有结果数据（测验成绩、作业评分、能力达成度）。

**补法**：
1. **随堂自测升级为计分小测**：现在 `s-quiz` 是「展开看答案」，改成「选择 → 判对错 → 记入本地成绩单」。
   一课一测，32 课累计生成「知识掌握热力图」——哪几个知识点全班都错，一目了然。**这是精准教学的直接抓手。**
2. **学习成果证书/徽章**：完成度 100% + 测验达标 → 生成一张带学号的可打印证书
   （纯前端 canvas 就能画）。低成本、高展示度，申报材料放一张截图很加分。
3. **作业提交留痕**：现在「展开作业」只是展开提示。可加一个「作业提交」输入框，
   粘贴提交链接/文本，存本地；导出档案时一并带出。

### 🟠 P1 — 没有课程级的内容检索引擎（AI 助教能力被封在小盒子里）

**现状**：搜索是**关键词子串匹配**（`IDX.filter(...indexOf...)`），306 条章节索引。
搜「怎么让 AI 输出表格」这种自然语言问题，大概率搜不到。

**缺什么**：「智能体」的核心能力是**理解意图**，不是匹配字符串。现在的 AI 助教
只在自己那个浮窗里工作，站内搜索是另一套笨办法，两者割裂。

**补法**：
1. **AI 助教接入全站检索（RAG）**：把 306 条章节索引 + 课时正文喂给助教做检索增强，
   学生问「温度参数怎么调」→ 直接定位到第 2 课 `s-temp` 小节并给出上下文。**这是智能体大赛最想看的东西。**
2. 搜索框支持自然语言：找不到就自动转给 AI 助教。**一个入口，两种能力。**

### 🟠 P1 — 教师端只能「事后看」，不能「事中干预」

**现状**：老师拖入 JSON 才能看报表，看完也是历史数据，无法干预。

**补法**：
1. 「**预警名单**」：完成度连续两周不涨、或某课停留时长异常短（可能没看）→ 自动列出。
2. 「**班级横向对比**」：同一课在不同班级的完成度对比（多拖几份档案即可）。
3. 「**一键回复高频提问**」：高频提问 Top12 旁边加一个「生成讲解」按钮，调用助教生成一段标准答案，
   老师审核后发到群里。**从「看数据」变成「用数据」。**

### 🟠 P1 — 无障碍与移动端没做过系统验证

**现状**：设计系统很规范（两主色、禁行内样式），但：
- 375 个按钮、176 张表格，**表格在手机上必然横向滚动**（虽有 tablewrap）；
- 没有做键盘全站可达性测试、没有 `aria-*` 系统检查、没有对比度检查。

**补法**：给 `check_site.js` 加两类新检查——**对比度**（读 site.css 变量算 WCAG 比值）、
**ARIA 完整性**（按钮必须有可访问名）。零成本把「无障碍」写进申报材料，
这是当前加分项，多数申报项目都没做。

### 🟡 P2 — 缺「教与学的证据链」材料

**现状**：技术做得扎实，但**没有任何一份面向评委的说明文档**：
- 课程设计理念 / 学情分析 / 教学策略 / 成效数据，都是散的；
- 没有「一个学生完整学习一次课」的截图流；
- 没有「老师用看板调整教学」的案例。

**补法**：写一份 **《教学设计说明》**（不是 README，是给评委看的），包含：
1. 课程目标 → 32 课的能力映射表；
2. 学情分析方法（用你自己看板里的话说：完成度分布、逐课完成矩阵、高频提问）；
3. 至少 1 个**真实教学案例**：「第 N 课完成度只有 40% → 发现是 `s-xxx` 太难 → 补了讲解 → 下次 85%」；
4. 技术架构图（离线底座 + 可选云端 + AI 助教 + 数据看板）。

## 四、建议的补强顺序（按性价比）

| 序号 | 做什么 | 工作量 | 申报价值 | 备注 |

| 2 | **随堂自测升级为计分小测 + 掌握热力图** | 中 | **高** | 补上「学习成效可测量」这块最大的洞 |

| 5 | **学习成果证书生成** | 小 | 中 | 展示度强，成本低 |
| 6 | **搭建最小上报端点**（把 `lt_endpoint_v1` 用起来） | 中 | **高** | 离散快照 → 连续数据流 |

## 五、两个申报方向的差异化打法

### 方向 A：智慧课程认定
评委看的是**课程建设规范性与成效**。重内容、重数据、重成效。
- 主打：内容完整度（32 课全配演示）+ 学情看板 + 完成度数据 + 计分小测成效；
- 补齐：完整数据流（不止离散快照）、成效量化（前后对比）；
- 叙事线：**「以学情数据驱动的精准教学改革」**。

### 方向 B：教学智能体大赛
评委看的是**智能体本身的能力与创新**。重 AI、重交互、重技术。
- 主打：AI 助教 + 全站检索（RAG）+ 教学决策看板 + 零依赖架构；
- 补齐：助教必须能**检索全站内容作答**（现在的离线助教太弱），最好能**多轮对话 + 引用出处**；
- 叙事线：**「一个懂课程内容、能陪学生学、能帮老师判的课程智能体」**。

> 两个方向**不冲突**，但**不要用同一份材料**。智慧课程要「成效数字」，
> 智能体大赛要「能力演示」。同一套代码，两种讲法。

## 六、一句话总结

**技术底子够硬，申报材料偏虚。**
你缺的不是功能，是 ①**一条可选的云端数据通路**、②**可测量的学习成效**、③**把技术翻译成教学故事**。
前两条各做一件事（起上报端点 / 计分小测），第三条写一份文档，申报竞争力会有质的变化。
