本课导读模块三

前面几课一直在给 AI 加东西：第 8 次课加技能、 第 18 次课接连接器、 第 28 次课让它记住你。 加到现在，该换个方向问了：这些东西是谁拼起来的，各自拿了多少权力，干完之后怎么查。

DeepSeek-Harness 给出的答案是「一切皆插件」—— 模型、工具、技能、会话、沙箱、存储、循环、调度、界面，全都是可以单独换掉的插件。 拆开看的好处是自由组合，代价是每一块你都得单独查一遍：它从哪来、要什么权限、出问题换掉它行不行。

现象卡在哪
装完一个插件，AI 突然能删文件了权限是插件带进来的，你没看过它要了什么；等发现时文件已经没了
任务跑完结果不对，只会说「它错了」中间十几步没有任何记录，不知道错在第几步，也就没法只改那一步
群里说「开 PTC 模式效果更好」，跟着开了也没变好模式是执行策略的组合，不是质量等级；换模式没换任务，等于没换
为了不弹确认框，直接给最高权限弹窗是在替你把关；关掉它，第一次越界就发生在你看不见的地方
提前说清楚 本课不部署 DeepSeek-Harness。它是 2026 年 8 月才开放的开发者预览版， 要自备开发环境、模型 API Key，课堂不要求你装。我们用你已经装好的 WorkBuddy 的「专家·技能·连接器」来看同一套插件化思路—— 看明白了结构，换任何一款 Agent 框架你都能自己上手。
本课三条主线，五个实操全挂在上面：① 能力是拼出来的，每个插件单独查来源和权限； ② 权限按任务给最低那一档，Full Access 不是默认项；③ 跑完必须留下一条能回放的记录。

本课事实口径核对日期 2026-09-26：DeepSeek Harness（DSH）v0.1 开发者预览版于 2026-08-13 开放测试并以 MIT 协议公开源代码（据澎湃新闻当日报道）； 「一切皆插件」为官方对架构的概括表述。三档权限与四种模式的整理来自公开技术资料与券商技术评测， 各来源表述一致；其插件内核据公开技术资料为 TypeScript + Cordis 插件体系（非官方一手口径，仅供参考）。
DeepSeek-Harness 迭代很快，命令、界面名称与功能以官方最新文档为准。

  1. 说出 Agent 框架里哪几类东西被做成了插件，并能在 WorkBuddy 的「专家·技能·连接器」里指出对应入口；

一、插件化内核：能力是拼出来的开局

「Harness」这个词原本指马车的挽具——把马和车连起来的那套皮带。 用在 AI 上，指的是围绕大模型搭起来的那一整套运行系统： 模型负责「想」，Harness 负责让它看得见环境、拿得到工具、能一步步把事做完。

DeepSeek-Harness 的做法是把它彻底拆开：模型、工具、技能、会话、沙箱、存储、循环、调度、界面， 每一块都是插件，可自由替换、灵活重组。这就是「一切皆插件」。

插件它负责什么换掉它，会变的是什么你要查什么
模型 真正「想」的那一个 推理能力、速度、价格 哪家提供的、按什么计费、数据是否出网
工具 读文件、跑命令、搜网页这类具体动作 它能干的事的范围 每个工具能碰哪些目录、要不要联网
技能 某一类事的固定做法（含脚本与模板） 活干得规不规范 谁写的、上次更新是什么时候
会话 / 存储 记住聊过什么、材料放哪 跨任务能不能接得上 存在本地还是云端、多久清一次
沙箱 限定它能动的边界 越界时是被拦下还是直接执行 拦下之后是弹窗确认，还是直接拒绝
循环 / 调度 「想一步、做一步、看结果、再想」这个节奏 跑几轮停、能不能派子任务 有没有步数上限、会不会空转
UI 你看到的界面 操作和查看方不方便 轨迹、权限开关这类入口在不在界面上

在 WorkBuddy 里对照着看

课堂不部署 DeepSeek-Harness，但插件化这件事在 WorkBuddy 里看得见—— 左侧边栏那个入口就叫「专家·技能·连接器」，三个词，三类可插拔的东西。

DeepSeek-Harness 的插件WorkBuddy 里对应的观察点看什么
模型对话区的模型选择当前这条任务用的是哪个模型
工具 / 连接器「连接器」标签页它连了哪些外部服务、各自能读能写什么
技能「技能」标签页（含「我安装的」）装了几个、来源是市场还是别人给的
角色预设「专家」标签页专家是「带着身份干活」的预设，换一个干法就变了
沙箱 / 范围工作空间（工作目录）它能写的范围就是这个目录

上表是课堂对照用的类比，用来帮你建立「框架是拼出来的」这个印象， 不是任何一方的官方架构说明；两边的实现并不相同。

插件化是方便，不是免责 能自由组合，意味着能力边界由你装的东西决定。 而插件不是说明书，是可执行代码——装上就能跑，跑起来就有权限。 所以规矩只有一条：每个插件单独查三件事——谁做的、多久没更新了、它要什么权限。

分三节，一节一类：
第一节【专家】、第二节【技能】、第三节【连接器】。

每节一张表，每行五列，一列都不能空：
| 名称 | 属于哪一类（模型 / 工具 / 技能 / 角色预设 / 外部服务） | 它拿到什么权限 | 换掉会怎样 | 来源 |

填表规则：
1. "它拿到什么权限"必须写具体到动作，例如"只读工作目录""可写工作目录""可调用外部接口并写入"；
   不许写"部分权限""较高权限"这种含糊说法；
2. "换掉会怎样"写清对结果的影响，只写一种：结果会变 / 只是变慢 / 没影响，并给一句理由；
3. "来源"只能填这四个之一：官方市场 / 他人分享 / 自己创建 / 系统内置；
4. 某一类一个都没有，就写"当前未安装任何 XX"，不许空着、不许编。

写完后在文件末尾加一段"【最该复查的一个】：在三节里挑出一个最需要复查来源与权限的，
写清为什么是它（提示：优先挑来源不明确、或者权限明显超出它用途的那一个）。

  3. 把下面这段指令发进去，让它按你的核对结果补一遍 补的是它漏掉的判断，不是让它重写一遍。
逐行复查 01-插件清单.md，只做这三件事，追加进文件，标题为"【人工核对】"：

1. 找出"来源"一列里填得含糊或我存疑的行，逐行写清疑点是什么、该怎么查证；
2. 找出"它拿到什么权限"里超出该项用途的行（例如一个只做格式转换的插件却可写整个工作目录），

  1. 三节表都在，「来源」一列没有空白行，也没有写「未知」以外的含糊词 空着说明它没真去查，只是套了个模板。

    写得太虚：补一句「权限必须写成可判断的动作：读 / 写 / 联网 / 调用接口，不许用程度词」。

    它说都正常：让它按「来源不明 / 权限超出用途 / 长期未更新」三类逐个过一遍，每类至少报一条或写明「无」。

二、三档权限：按任务给最低那一档本课核心

装完新工具的人最容易做的一件事，是把确认框关掉—— 每写一次文件弹一次窗，太烦了，索性给它最高权限，让它自己跑。 问题是，那个弹窗不是啰嗦，它是唯一一次让你在动作发生前看见它的机会。

DeepSeek-Harness 把权限分成三档，WorkBuddy 一类工具也是同样的思路： 不是「给不给」，而是「这件事需要多少」。

档位它能做什么越界时发生什么什么时候用它
Read Only
只读		 只能读文件、取信息，不能改任何东西、不能执行写操作 根本不会走到那一步——写操作不在它的能力里 看代码、看资料、问问题、让它给方案；最安全，也最适合第一次跑
Workspace Write
工作区写入		 可以在指定工作目录内读写文件、跑受限命令 碰到工作区之外的地方，弹窗要你确认，或者直接被沙箱拒绝 日常干活：写功能、改文件、整理材料——默认就用这一档
Full Access
完全访问		 可执行范围更广的操作，包括工作区之外的系统级动作 没有边界可越——它做的事你只能在事后看记录 明确需要且环境可回滚时才用：可信环境下的自动化流水线
可运行演示 ① 同一个任务，三档权限跑出来的结果差在哪
—产出文件
—越界动作
—事后可恢复
教学示意，非实测数值。任务与执行过程为本课虚构的课堂示例， 用来演示三档权限的行为差异；真实工具的具体弹窗行为随版本不同，以你实际使用的版本为准。
红线：权限按任务需要给，不按省事程度给 判断顺序是先看这件事要不要写东西 → 再决定给哪一档， 不是「先给最高，出问题再说」。
一句「用 Full Access 跑得更快」听起来有理，实际是把事前确认换成了事后挽回—— 而文件删掉之后，事后是挽回不回来的。

补充规则：
1. 每层至少补满 4 条动作，每条写一个具体动作，不许写"做一些修改"这种；
2. 第三层的四类动作（发送 / 删除 / 覆盖 / 授权）一条都不许挪到前两层；
3. 每条动作后面用括号写清风险等级：低 / 中 / 高；
4. 有歧义的动作（例如"整理文件"可能包含删除）必须拆成两条，把带删除的那条放进第三层。

写完在文件末尾加"【本卡的四条判据】：用四句话写清，一个动作该放哪一层，判断时依次问哪四个问题。

第 2 步 · 让它自检一遍三类动作有没有放错层

  1. 把下面这段指令紧接着发出去 这一步才是重点：它自己填的卡，也要它自己按规则重查一遍，你只核对它查得对不对。
按下面三条逐条复查 02-三层权限卡.md，追加进文件，标题为"【分层自检】"：

1. 发送、删除、覆盖、授权这四类动作，是不是全部都在第三层？逐类点名回答"在 / 不在"；
2. 前两层里有没有藏着带删除或覆盖含义的动作？有就逐条点出来，并给出移进第三层后的写法；
3. 有没有一条动作同时属于两层？有就按"就高不就低"处理，写清改后放在哪一层。

复查结论用一句话开头：这张卡现在能不能直接用。不许改写前面已有的内容。

做到这三条，就算做完了

  1. 三层各有至少 4 条动作，且每条都带风险等级 只有两三条说明它在敷衍；没标风险等级说明它没真判断。
    条数不够：补一句「每层补全到 6 条，每条必须带（低/中/高）」。
  2. 【分层自检】里四类动作逐类点名，且结论是「全部在第三层」 只写「已检查」不算数。
    它跳过了某一类：把四类动作名再发一遍，要求「逐类回答在或不在」。
  3. 「本卡的四条判据」是可执行的问句，不是口号 「注意安全」不算判据；「这个动作改完之后能不能一键撤销」才算。
    写成了口号：补一句「每条判据必须是一个能回答是或否的问题」。

三、四种模式：按任务换组合方法

技术群里最常看到的一句话是「开 XX 模式效果更好」。这句话的问题在于， 它把模式当成了质量等级——好像档位越高，活就干得越好。

实际不是。模式是执行策略的组合：这一趟给它哪些工具、允不允许它自己写程序串步骤、 要不要保留计划能力。任务没变，换模式只是换了干法。

模式保留哪些能力代价 / 限制什么时候换它
标准 完整编码与通用智能体能力：编辑文件、跑命令、用技能、做计划、派子任务 工具多，步数也多，出错时要看的记录更长 默认用它——日常任务先从这里起步
PTC 在标准基础上，允许模型写一段程序把多步操作串起来执行 那段程序本身也会出错；出了错，错的是代码不是步骤 多步操作要反复跑、流程需要固定下来的时候
极简 只保留跑命令和改文件两个核心工具 没有计划、没有子任务，复杂任务它自己拆不动 问题最小化复现、做基准测试、只想让它干一件小事
创造 可自定义 Agent 预设、检查运行时、在内存里试插件 面向插件开发，日常干活用不上，也更容易改坏配置 你要写自己的插件、调预设的时候
可运行演示 ② 同一个任务换四种模式：变的是干法，不是质量
—可用工具
—执行步数
—出错时看什么
教学示意，非实测数值。工具数与步数是本课为讲清差别而设的示意值， 不同版本与不同任务差别很大；这里要记住的是「换模式=换工具组合」，不是数字本身。
选模式的顺序：先用标准跑通，再考虑要不要换 跑不通，先看是任务说得不清还是工具不够—— 十次里有八次是前者，换模式解决不了。
真要换，记住两句话：步骤要反复跑 → 试 PTC；只想干一件小事 → 试极简。 创造模式是给写插件的人的，日常别碰。

四、事件流与轨迹回放：查错不查功收口

任务跑完，结果不对。大多数人的第一反应是「它不行」或者「再跑一遍」—— 两种都没用，因为你不知道错在第几步。再跑一遍，只是再赌一次。

Agent 框架给你的那件东西叫事件流：它把每一步发生了什么按顺序记下来。 把这串记录从头放到尾看一遍，就是轨迹回放。

记录里的角色记的是什么回放时你要看什么
SYSTEM开场设定：允许它做什么、有哪些工具权限范围是不是比你想的大
USER你说的原话有没有说清边界（只写新文件 / 不许删）
CONTEXT它拿到的背景：工作区、可用工具清单它看到的东西对不对
ASSISTANT它的思考和打算哪一回合开始跑偏
TOOL实际调用的工具与参数有没有调用到你没让它用的东西

回放不是重看一遍热闹。它是带着三个问题去看的：有没有越界、错在哪一步、在哪一步失败后开始空转。

可运行演示 ③ 一条事件流从头放到尾：越界发生在第几步
①收指令
②列目录
③写清单
④改标题
⑤汇报
教学示意，非实测数值。这条事件流为本课虚构， 用来演示「回放时该盯哪几类问题」；真实产品的记录字段与展示方式以官方为准。
回放的价值是发现错误，不是证明正确 一条记录从头放到尾、每一步都规规矩矩，也不能说明结果天然正确—— 它只能说明过程里没查出问题。
所以别把「我看了回放，没问题」当成验收结论。验收看的还是产出物： 文件对不对、有没有多删东西、原先的约束有没有被遵守。

1「一切皆插件」这个说法，指的是什么？
  • A. 所有功能都做成了浏览器插件，装在浏览器里就能用
  • B. 模型、工具、技能、会话、沙箱、存储、循环、调度、界面等都是可替换的插件
  • C. 它只能跑别人写好的插件，自己不能写
  • D. 插件越多，这个框架就越安全
答案：B。官方的概括是「模型、工具、技能、会话、沙箱、存储、循环、调度、UI 等 Agent 能力均由插件组合而成，可自由替换、灵活重组」。 A 把「插件」理解成浏览器插件，跑偏了；C 说反了，插件恰恰是可以自己写的； D 是常见误解——插件是多是少和安不安全没关系，每个插件的来源与权限要单独查， 装得越多要看的越多。
2一个只读类的分析任务，最合适的权限档位是？
  • A. Full Access，省得弹窗打断它
  • B. Workspace Write，反正它也不会真写
  • C. Read Only，按任务需要给最低那一档
  • D. 先给 Full Access，跑完再收回来
答案：C。规矩是按任务需要给，而不是按省事程度给。 A 和 D 都把「事前确认」换成了「事后挽回」，而删除、发送这类动作事后是挽回不回来的； B 也不对——「它不会真写」是你猜的，给多了权限，越界就发生在你看不见的地方。

  • A. 把整理好的清单发给任课老师
  • B. 删掉工作目录里上一轮的临时文件
  • C. 连接我的网盘账号并同步材料
  • D. 在工作目录里新建一个清单文件
答案：ABC。三类动作的共同点是不可恢复或影响范围外扩： 发出去收不回、删掉找不回、授权等于把门打开。 D 是在指定工作目录里新建文件，属于 Workspace Write 的正常范围， 把它也放进需确认，会让每张卡都变成高风险，等于没排序。
4有人说「开 PTC 模式效果更好」，对这句话最恰当的判断是？
  • A. 对，PTC 是最高档，档位越高活干得越好
  • B. 不对，模式是执行策略的组合，不是质量等级，要看任务对不对得上
  • C. 不对，因为 PTC 模式有安全风险，任何任务都不该用
  • D. 说不好，得看用的是哪家模型
答案：B。模式决定的是「这一趟给它哪些工具、允不允许它写程序串步骤」， 换模式是换干法，不是提质量。任务跑不通，十次里有八次是任务本身没说清，换模式解决不了。 C 走到另一个极端——PTC 在「多步操作要反复跑」时正好合适，不是不能用； D 答非所问，模型是另一个插件维度。
5判断：一条事件流从头放到尾、每一步都规规矩矩，就说明结果是对的。
  • A. 正确
  • B. 错误
答案：B（错误）。回放的价值是发现越界、错误和失败位置，不是证明结果天然正确。 过程没查出问题，不等于产出物没问题——验收看的还是文件对不对、有没有多删东西、 原先的约束有没有被遵守。把「我看了回放，没问题」当验收结论，是把手段当成了目的。
6回放时，下面哪一处最值得优先盯？
  • A. USER 那一行，看自己原话写得好不好
  • B. ASSISTANT 的思考，看它文笔是否通顺
  • C. TOOL 那几行，看它有没有调用到你没允许的东西
  • D. 最后一行结论，看它有没有说「已完成」
答案：C。越界几乎都发生在工具调用上——说好只写新文件，它却改了已有文件， 这种事只看结论看不出来。 A 值得顺带看（边界写没写清），但不是回放的重点；B 没意义，通顺不等于做对了； D 最不可靠，「已完成」是它自己说的，不是验收结论。

本课要点回顾

这一课要带走五件事

  1. 主线只有一句：能力是拼出来的，权限按任务给，跑完要能查；本课不部署 DeepSeek-Harness，用它讲结构；
  2. 插件化内核：模型、工具、技能、会话、沙箱、存储、循环、调度、UI 都是可换的插件，每个插件单独查来源与权限；
  3. 三档权限：Read Only 只读 / Workspace Write 工作区内读写 / Full Access 完全访问；默认用中间那档，Full Access 不是默认项；
  4. 四种模式是执行策略的组合，不是质量等级：标准起步，步骤要反复跑试 PTC，小事用极简，创造模式留给写插件的人；
  5. 事件流与轨迹回放盯三类问题：越界 / 错误 / 空转；回放能发现错误，但不能证明正确——验收看的还是产出物。

下一步棋：今天你一直在给 AI 划边界——能碰什么、怎么干、干完怎么查。 下一课 AI 学习助手与知识管理 换一个场景： 把 AI 用在「学知识」上。那时同样适用今天这条规矩，只是边界换成了另一种—— 它可以替你讲，但不能替你懂。

课后作业单选 / 多选 / 判断

下面这套题可直接复制提交。点一下展开，再点框内右上角「复制」就能整段拿走。

1.（单选）DeepSeek-Harness 采取"一切皆插件"的设计思路，这里的"插件"指的是？
A. 装在浏览器里的扩展程序
B. 模型、工具、技能、会话、沙箱、存储、循环、调度、界面等可替换的组成部分
C. 只能由官方提供、用户不能自行编写的模块
D. 用来提升模型推理能力的加速组件
【答案】B
【解析】官方概括为"Agent 能力均由插件组合而成，可自由替换、灵活重组"。A 把插件理解成浏览器扩展，跑偏；C 说反了，插件恰恰可以自己写；D 与插件无关，那是模型侧的事。

2.（单选）一个只需要读取资料并给出分析结论的任务，最合适的权限档位是？
A. Full Access，避免弹窗打断执行
B. Workspace Write，多给一点更保险
C. Read Only，按任务需要给最低那一档
D. 先给 Full Access，任务结束后再收回
【答案】C
【解析】原则是"按任务需要给，而不是按省事程度给"。A、D 把事前确认换成了事后挽回，而删除、发送这类动作事后无法挽回；B 也不对，多给的权限会在你看不见的地方被用上。

3.（多选）下列动作中，应当放进"每次都要先问我"这一层的有？
A. 把整理好的清单发送给老师
B. 删除工作目录里的临时文件
C. 连接个人网盘账号并同步材料
D. 在工作目录里新建一个清单文件
【答案】ABC
【解析】A、B、C 的共同点是不可恢复或影响范围外扩：发送收不回、删除找不回、授权等于把门打开。D 属于工作区内的正常写入，若也列入需确认，会把所有动作都判成高风险，等于没有排序。

4.（多选）关于 PTC 模式，下面说法正确的有？
A. 它是在标准模式基础上，允许模型编写程序把多步操作串起来执行
B. 它适合多步操作需要反复执行、流程需要固定下来的场景
C. 它是最高档模式，任何任务开它就一定效果更好
D. 它写的那段程序本身也可能出错，出错时错的是代码而非步骤
【答案】ABD
【解析】C 是典型误解：模式是执行策略的组合，不是质量等级，任务对不上就只是换了个干法。ABD 都符合公开资料对 PTC 的描述，其中 D 提醒了它的代价——串步骤的程序本身也是出错点。

5.（判断）一条事件流从头放到尾，每一步都规规矩矩、没有越界和失败，就足以证明这次任务的产出结果是正确的。
【答案】错误
【解析】回放的价值是发现越界、错误和失败位置，不是证明结果天然正确。过程没查出问题，不等于产出物没问题——验收仍要看文件对不对、有没有误删、原先的约束是否被遵守。

6.（多选）回放一条事件流时，为了找出问题，应当重点检查哪些方面？
A. TOOL 记录里有没有调用到 USER 原话未允许的动作
B. 有没有哪一步的工具参数明显写错（路径、文件名、类型判断）
C. 有没有连续两步在做同一件事，或失败后原地重试
D. 最后一行是否写了"已完成"
【答案】ABC
【解析】三类问题对应越界、错误、空转，都是回放要盯的。D 最不可靠——"已完成"是 AI 自己下的结论，不是验收依据；只看这一行，等于让它自己给自己打分。
评分看什么 本课作业按三处判断：一是能不能分清「按任务给权限」与「按省事给权限」， 尤其对发送、删除、授权三类不可恢复动作的态度； 二是提到模式时，是否把它理解为执行策略组合而非质量等级； 三是对轨迹回放的定位——是「用来发现越界、错误和空转」，还是误当成「结果正确的证明」。
