本课导读模块一收尾

前面五次课，我们一直在用别人家的电脑算 AI：你提问题，它算完把答案送回来。 这一课把这件事反过来——把模型下载到你自己的电脑上，用你自己的 CPU 算。

先回答三个很具体的问题，它们决定了这课值不值得学：

  • 断网了，你的 AI 还能用吗？——云端模型不能。它断网即废。
  • 你输入的内容，存在谁那里？——云端模型存在厂商的服务器上。
  • 同一个问题问几百遍，你会心疼吗？——云端按量计费会，本地不会。

本地部署换来的三样东西是：数据不出门、断网也能用、反复调用不要钱。 代价也很明确：能力明显更弱。所以本课的结论不是「本地更好」， 而是——各有各的位置，知道什么时候该用哪个，才是真的会用工具。

提前说清楚 本课默认从 qwen3:1.7b（17 亿参数）起步。它答得不会很聪明，这很正常。 它的价值不出在「聪明」上，而出在前面那三样东西上。

学习目标

学完这一课，你应该能——

  1. 说清本地模型与云端模型的三点核心差异，并能在具体场景里做出选择；
  2. 独立完成 Ollama 的安装、模型目录整改与三步环境自查；
  3. 按自己电脑的内存大小选对模型档位，并理解「先小后大」这条铁律；
  4. 用三种方式调用本地模型：交互式、一次性提问、程序 API 调用；
  5. 用 Modelfile 做一个有固定人设的专属助手；
  6. 遇到「跑得慢」「命令找不到」「下载失败」时，能自己判断原因并对症处理。

一、为什么要本地模型认知地基

先说一个日常现象：你在网页里打开豆包、千问、DeepSeek，输入一句话，几秒后答案就出来了。 这个过程里，你的电脑几乎没有做什么计算——它只是把问题发出去，再把答案收回来。 真正干活的是厂商机房里的服务器。

☁️厂商服务器
真正在这里算
💻你的电脑
算也在你自己这儿
🔌网络

教学示意：真实链路还有 DNS 解析、负载均衡、限流排队等环节，这里只保留「谁在算、数据去哪」这一层。

本地与云端的三点对照

维度云端模型（豆包 / 千问 / DeepSeek）本地模型（Ollama）
数据去向提问内容要传到厂商服务器数据不出本机，只有你自己的电脑知道
网络依赖断网即不可用；高峰期可能要排队装好之后可离线使用
能力水平能力强，能联网查最新资料受参数规模限制，明显更弱；不能联网查新
成本按量计费或订阅一次性硬件投入，之后反复调用不花钱
最适合复杂任务、需要最新信息隐私敏感、要求离线、需要批量重复调用
本课要反复念的一句话 本地不是「更好」，是「各有位置」。

二、Ollama 是什么

Ollama 是一个在本地运行开源大模型的运行时（runtime）。 说人话：它像「大模型的应用商店 + 播放器」——装好之后，一条命令下载模型，一条命令开始对话。

它把原本很麻烦的事情都替你办了：

  • 不用配 CUDA，不用编译源码，不用 Docker，也不用先装 Python 环境；
  • 有可用显卡时自动用显卡加速，没有显卡时自动切成 CPU 推理（结果正确，但明显更慢）；
  • 装好后会在本机开一个服务，默认监听 http://localhost:11434，供你自己的程序调用。
注意 本课不讲具体版本号。Ollama 迭代很快，讲了就容易过期。 我们只教一条自查命令：ollama --version——版本号会变，命令不会变。

三、安装与环境核查10 分钟兜底

到 Ollama 官网下载对应系统的安装包（Windows / macOS / Linux），双击安装即可。装完之后先做三步自查。

  1. 装好了吗打开 PowerShell（Windows 键 → 输入 powershell → 回车），输入 ollama --version。有版本号输出就说明装好了。
  2. 模型装在哪Ollama 默认把模型放在系统盘：C:\Users\你的用户名\.ollama\models。一个模型 1~5 个 GB，装三四个 C 盘就红了。解决办法见下一节「坑位①」。
  3. 我有多少内存「此电脑」右键 → 属性，或任务管理器 → 性能页。内存（RAM）那一行。记住这个数字，选模型档位要用它。
跑不通怎么办（三种情况及对策）
  • 提示「不是内部或外部命令」 → 关掉终端重新打开，让环境变量生效；还不行就重装一次并勾选「添加到 PATH」。
  • 模型一直下不动 → 降到最小那一档 qwen3:0.6b（约 500 MB）。
  • 确实装不上 → 和邻座共用一台，作业里注明「共用设备」即可。

命令作用什么时候用

第 1 步 · 按内存定模型（规则定死，别自己换）

  1. 内存 ≥ 8 GB → 用 qwen3:1.7b；内存 < 8 GB → 用 qwen3:0.6b 0.6b 约 500 MB、1.7b 约 1.2 GB。档位选大了会卡到没法上课，先按这条规则来。

第 2 步 · 按顺序跑完这三条（4 分钟）

# ① 拉模型（把 qwen3:1.7b 换成你该用的那一档）
ollama pull qwen3:1.7b

# ② 确认下载成功
ollama list

# ③ 进入对话（进去直接打字就能聊，输入 /bye 退出）
ollama run qwen3:1.7b

第 3 步 · 进去之后做两件事（3 分钟）

  1. 问它一个你专业上的问题比如「用一个生活例子解释什么是过拟合」，看它答成什么样。
  2. 输入 /bye 退出这是退出对话的方式——直接关窗口有时会把进程留在后台。

第 4 步 · 做到这三条，就算做完了

  1. ollama list 里能看到刚拉的模型看不到说明第 ② 条的 pull 没跑完—— 重新跑一次，注意进度条走到 100% 才算完。
  2. 跟它说过至少一轮话回车后迟迟没反应，是模型还在加载，等十来秒正常； 超过一分钟还没动静，Ctrl+C 退出重进一次。
  3. 断网之后它还能答这是本地模型最核心的价值—— 把 Wi-Fi 关掉再问一句，它照样回你。做不到就不是真本地。

五、四个必知坑位

这四个坑，几乎每个第一次装 Ollama 的人都会踩至少一个。提前知道，能省你半小时。

坑位① 模型默认装在系统盘

现象：C 盘空间莫名其妙少了几个 G，甚至变红。
原因：模型文件默认存在 C:\Users\<用户名>\.ollama\models（macOS / Linux 是 ~/.ollama/models）。
解决：装完的第一时间就配置环境变量 OLLAMA_MODELS，把目录改到非系统盘，然后重启 Ollama 才生效。 

# 方式一：图形界面（推荐给第一次做的人）
# 1) Win 键搜索"环境变量" → 打开"编辑系统环境变量"
# 2) 点"环境变量" → 在"用户变量"里点"新建"
# 3) 变量名填 OLLAMA_MODELS，变量值填 D:\OllamaModels
# 4) 确定后，右下角托盘图标右键退出 Ollama，再重新打开

# 方式二：命令行为当前用户永久写入（改完同样要重启 Ollama）
[Environment]::SetEnvironmentVariable("OLLAMA_MODELS", "D:\OllamaModels", "User")

# 验证：新开一个终端，应该能打印出路径
echo $env:OLLAMA_MODELS

坑位② 运行卡顿、响应极慢

先确认一件事：你的电脑有没有独立显卡？
没有独显，就是 CPU 推理，慢是正常的，不是你装错了。 想变快，最快的办法是换更小参数的模型，而不是重装 Ollama。

坑位③ 命令找不到

输入 ollama 提示「不是内部或外部命令」。
解决：重启终端（或重新打开 PowerShell）；仍不行则卸载后重新安装，安装时勾选「Add to PATH」。

坑位④ 一口气拉一个太大的模型

现象：下载几 GB 要很久，下完了内存不够，跑不起来。
解决：先拉最小的一档跑通，再按需换大的。 跑不起来的大模型，等于没有模型。

六、按内存选档位本课核心

模型的「档位」指的是参数量（0.6b = 6 亿参数，7b = 70 亿参数）。 参数越大越聪明，也越吃内存和显存。所以选模型的唯一依据，是你电脑的内存。

可运行演示 ② 按内存选档位：拖一下，看该拉哪个模型
我的电脑内存 8 GB
qwen3:1.7b推荐档位
1.4 GB模型文件大小
4 GB+所需内存
12–18 字/秒CPU 推理速度（示意）
教学示意，非实测数值。速度受 CPU 型号、内存带宽、是否后台占用影响很大，这里只用来建立「参数越小越快」的定性认识。

deepseek-r1:7b4.7 GB8 GB+推理链、数学与逻辑题

qwen3:14b9.3 GB12 GB+16 GB 内存可尝试

为什么「文件大小」能当内存参考

Ollama 默认使用 Q4 量化——把模型的权重压缩存储，体积大幅缩小、回答质量损失有限。 压缩之后，模型文件大小就是估算所需内存的可靠参考：一个约 2.5 GB 的文件，基本就要 6 GB 左右内存才跑得舒服。

铁律 先拉最小的一档跑通，再按需换大的。

八、三种调用方式

同一个模型，有三种用法，对应三种完全不同的场景。

方式命令形态有记忆吗典型场景
① 交互式ollama run qwen3:1.7b有，记得住上一轮自己聊天、调试人设
② 一次性ollama run qwen3:1.7b "问题"没有，答完即退脚本、批处理
③ 程序 API发 HTTP 请求到 localhost:11434看你自己怎么传写进自己的程序
 
# ① 交互式：进去一直聊，/bye 退出
ollama run qwen3:1.7b

# ② 一次性：命令后面直接带问题，答完就退出，不占着终端
ollama run qwen3:1.7b "用一句话解释什么是机器学习"
「一次性」是给脚本用的 它的价值在于可以放进循环里：批量处理 100 个文件、100 条评论、100 份简历， 不用手动点 100 次。下面的 API 方式能力更强，一次性方式是它最省事的替代品。

九、用程序调用本地模型

Ollama 装好之后，在你的电脑上开了一个服务，地址是 http://localhost:11434。 localhost 的意思就是「你这台机器」。程序只要往这个地址发请求，就能用到你的本地模型。

它提供了两个端点：

  • POST /api/generate —— Ollama 自己的原生接口，简单直接；
  • POST /v1/chat/completions —— OpenAI 兼容接口，请求体格式和 OpenAI 完全一致。
为什么「兼容 OpenAI」这句话很值钱 它意味着——任何支持自定义 base_url 的客户端或代码，都能直接接过来用，一行代码都不用改。 你以前写的调用云端的程序，只要把地址换成 http://localhost:11434/v1，就变成在调你自己的模型了。
可运行演示 ③ API 调用全流程：请求长什么样、返回长什么样 
curl http://localhost:11434/api/generate -d "{\"model\":\"qwen3:1.7b\",\"prompt\":\"用一句话解释什么是神经网络\",\"stream\":false}"

import requests

resp = requests.post(
    "http://localhost:11434/api/generate",
    json={"model": "qwen3:1.7b", "prompt": "用一句话解释什么是神经网络", "stream": False},
    timeout=120,
)
print(resp.json()["response"])
演示里的返回内容是示意数据，用于说明字段结构；真实回答由你本机的模型生成，每次都会不一样。

两个端点的请求与返回长什么样

{
  "model": "qwen3:1.7b",
  "messages": [
    { "role": "system", "content": "你是一个简洁的助手。" },
    { "role": "user",   "content": "用一句话解释什么是神经网络" }
  ],
  "stream": false,
  "temperature": 0.7
}

{
  "id": "chatcmpl-1027",
  "object": "chat.completion",
  "model": "qwen3:1.7b",
  "choices": [
    {
      "index": 0,
      "message": { "role": "assistant", "content": "神经网络是……" },
      "finish_reason": "stop"
    }
  ],
  "usage": { "prompt_tokens": 24, "completion_tokens": 42, "total_tokens": 66 }
}

注意返回结构：choices[0].message.content 才是回答正文。 这套字段名和 OpenAI 完全一致——这就是「兼容」的全部含义。

做完你手上会有：一个能跑的 ask_local.py——用它在终端里跟本地模型一问一答。

第 1 步 · 把脚本存下来（2 分钟）

  1. 在你的 wb-试验 文件夹里新建 ask_local.py VS Code 或记事本都行，保存时编码选 UTF-8，否则中文会乱码。
  2. 把下面这份脚本整段复制进去点代码块右上角「复制」，别手抄——缩进错一处就跑不起来。
  3. 确认脚本里的模型名跟你本地的一致这行最容易出错—— 先用 ollama list 把名字复制出来，再替换脚本里的 MODEL = "..."。
# -*- coding: utf-8 -*-
"""
用 Python 调用本地 Ollama 模型 —— 完整可运行示例
依赖安装：pip install requests
运行前提：本机已启动 Ollama（装好后自动在后台运行），且 ollama list 里有 qwen3:1.7b
"""

import sys
import requests

OLLAMA = "http://localhost:11434"   # 本地服务地址：装好 Ollama 就有
MODEL = "qwen3:1.7b"                # 换成你 ollama list 里实际有的模型名


def ask(prompt, model=MODEL, timeout=120):
    """方式一：原生 /api/generate 接口，问一句答一句。"""
    resp = requests.post(
        f"{OLLAMA}/api/generate",
        json={"model": model, "prompt": prompt, "stream": False},
        timeout=timeout,
    )
    resp.raise_for_status()          # 出错时直接抛出，方便定位
    return resp.json()["response"]


def chat(question, model=MODEL, timeout=120):
    """方式二：OpenAI 兼容接口。把地址换成云端就能无缝迁移到别的模型。"""
    resp = requests.post(
        f"{OLLAMA}/v1/chat/completions",
        json={
            "model": model,
            "messages": [
                {"role": "system", "content": "你是一个简洁的助手，回答不超过两句话。"},
                {"role": "user", "content": question},
            ],
            "stream": False,
        },
        timeout=timeout,
    )
    resp.raise_for_status()
    return resp.json()["choices"][0]["message"]["content"]


def batch(questions, model=MODEL):
    """批处理：一个循环跑完一堆问题，这是本地模型最划算的用法（不花钱、不限次）。"""
    for i, q in enumerate(questions, 1):
        print(f"[{i}/{len(questions)}] {q}")
        print("   →", ask(q, model=model).strip().replace("\n", " "))
        print()


if __name__ == "__main__":
    # 首次使用先体检：连不上服务时给出人话提示，而不是一串报错
    try:
        requests.get(f"{OLLAMA}/api/tags", timeout=5).raise_for_status()
    except Exception as e:
        print("连不上本地 Ollama 服务，请检查：")
        print("  1) 托盘里 Ollama 图标在不在（没有就去启动它）")
        print("  2) 端口 11434 有没有被别的程序占用")
        print(f"  原始错误：{e}")
        sys.exit(1)

    q = "用一句话解释什么是人工智能"
    print("【原生接口 /api/generate】", ask(q))
    print("【兼容接口 /v1/chat/completions】", chat(q))

    # 批处理示例：把下面这行注释取消即可体验
    # batch(["什么是过拟合", "过拟合怎么解决", "举一个生活中的例子"])

十一、Modelfile：给模型定人设成果物

每次开一个新对话，都要重新交代一遍「你是什么角色、该怎么回答」，很烦。 Modelfile 就是解决这件事的：把规矩一次写清楚，之后随叫随到。

它最简的结构只有两行：

  • FROM —— 告诉它「你是谁的孩子」，基于哪个模型；
  • SYSTEM —— 告诉它「你要守什么规矩」：人设、口吻、边界。
可运行演示 ④ Modelfile 定人设：写规矩，看它守不守规矩
模型名（创建之后用它来启动）
演示里的回答是离线预置的示意文本，用于让你看清「人设写得不同，回答的边界就不同」。真实效果请在你自己电脑上跑。

创建与运行

# 假设 Modelfile 就放在当前目录（文件名可以就叫 Modelfile，无扩展名）
ollama create mybot -f Modelfile

# 之后只要这一行，它就永远是你定好的那个角色
ollama run mybot

# 看看自己创建过哪些模型（自定义模型也会出现在列表里）
ollama list

# 不想要了
ollama rm mybot
规律 人设写得越具体，模型越好用。 只写「你是个助手」等于什么都没说；把边界（只答什么、答不上来怎么办、一次说几句）写清楚，它就真的守规矩。
现成的 Modelfile 放在下面的动手做 ④ 里，照着改成你自己的。
动手做 ④·做一个「课程答疑助手」，给它定死规矩 约 10 分钟

  2. 把下面这份模板整段复制进去点代码块右上角「复制」，别手打——缩进和引号错了都跑不起来。
  3. 把 FROM 那行的模型名换成你本地实际有的先 ollama list 把名字复制出来再改。 模型名不对，create 一定失败。
FROM qwen3:1.7b

SYSTEM """
你是《AIGC应用与实践》课程的答疑助手。
只回答与本课程相关的问题；答不上来就直说"这个我不确定"，不许编。
回答要简短，一次不超过 5 句话。
"""

第 3 步 · 故意试它一下（4 分钟）

  1. 先问一个课程相关的问题比如「本地模型有什么好处」——看它答得是不是简短、在不在题上。
  2. 再问一个明显不相关的问题比如「今天中午吃什么」。它应该拒绝，因为 SYSTEM 里写着「只回答与本课程相关的问题」。

十二、边界与权衡：该用本地还是上云

这是本课最终要落到的能力——不是「会装」，而是会选。遇到一个具体任务，问自己三个问题：

  1. 数据敏不敏感？涉及学生隐私、公司内部资料、个人信息 → 优先本地。
  2. 要不要联网查新？需要最新资讯、实时行情、最新政策 → 必须上云，本地模型查不了。
  3. 对能力要求高不高？复杂推理、长文写作、代码重构 → 上云；简单分类、批量改写、格式转换 → 本地够用。
选本地
  • 学生的心理咨询倾诉内容
  • 公司还没发布的内部文案
  • 几百份简历的批量初筛打标签
  • 断网环境下的演示与教学
  • 要做上千次的重复性文本处理
选云端
  • 需要查最新资讯、实时数据
  • 写一篇有深度、要引用的长文
  • 复杂代码重构与调试
  • 多模态任务（看图、生成图/视频）
  • 偶尔用一次，不想占本机资源
回到主线 你们今天跑的 1.7b 确实不如云端聪明。但它是你的——数据不出门、断网能用、反复调用不要钱。 知道什么时候该用本地、什么时候该上云，才是真的会用工具。
