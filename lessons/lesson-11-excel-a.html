本课导读模块二 · 办公实战

上一课处理的是 Word，难点是「读着顺不顺」。这一课换成表格， 难点变成了一件事：数字对不对。 一叠发票、一批报销单据，交到 AI 手里几分钟就能出表—— 但快不等于对，它读了几张票、金额看错一位没有、同一张票算没算两遍， 你不问它就不说。而报销是要拿去给财务的。

一、票据交出去之前，先让它认字段、报家底地基

先看一句最常见的指令，和它的下场： 

帮我算一下这些发票一共多少钱。

（两分钟后）一共 10601.5 元。

问题是：你不敢把这个数报给财务。 它一共读了几张票？那张被印章盖住金额的算了多少？同一张票被扫进来两次算了两遍吗？ 你一样都不知道，而它不会主动告诉你——它只回答你问的那句。

所以第一步不是「让它算」，而是让它先把票认全、把家底报出来。 这就像请人帮你盘库：先让他报「有多少箱、哪些箱是空的、哪些箱标签看不清」， 你认可了他的盘点结果，再让他搬。盘点错了就纠正，搬错了要重搬一趟。

它到底是怎么处理你的表的

这一点必须讲清楚，因为它决定了你敢不敢把真实报销数据交给它。 下面三条是官方文档口径，不是推测：

官方口径（原文要点）对你意味着什么
数据本地执行不上传：所有数据在用户本地环境执行处理； 服务端仅处理数据片段，用后即弃，不保存、不用于模型训练 发票金额、报销人这类财务数据可以放心给它处理
Bash 命令沙箱：AI 操作与真实系统严格隔离； 文件系统隔离：只能访问预先授权的工作空间目录 它碰不到你没授权的文件夹，也改不动系统目录
默认安全设计：启动时仅拥有只读权限， 编辑文件、运行命令需显式用户批准 它会先给你看方案，你点了才动手

以上三条摘自 WorkBuddy 客户端用户文档「常见问题 · 数据安全说明」， 本站核对日期 2026-09-24。 另：官方文档「简介」页把「本地文件操作：可读取授权的电脑文件夹，进行批量处理」 与「数据分析：上传数据文件，自动分析和可视化」列为产品能力。

一个「不确定」，如实标出来 教案里把它概括为「本地 Python 沙盒」。官方口径里能查到的是 「Bash 命令沙箱」+「数据本地执行不上传」这两条， 并没有规定必须用 Python。 你在执行过程里通常会看到它生成一段脚本再执行， 但具体用什么语言跑，取决于模型与任务——这一点本站不确定，以你实际看到的为准。 反正对你来说不重要：你验的是输出的数字，不是它用的语言。

怎么把票据交给它

官方文档「实践三：数据分析并可视化」里写了两种把表交给它的方式 （本站核对日期 2026-09-24）：

方式怎么做什么时候用
拖入对话把票据图片 / PDF / Excel 文件直接拖到对话框临时处理一两张票
告诉路径在指令里写明文件在工作目录里的位置要连续处理多份、或要它另存新文件

本课四个实操统一用第二种——把素材存成文件放进工作目录， 指令里写清文件名。这样它能自己另存、你能自己打开核对， 不会因为「文件只在对话里」而没法验收。 重要资料只放副本：素材统一放在工作目录里的 input 下， 你本人的真实票据不要往工作目录里放原件。

沙盒与权限边界：这一课的底线 它只在你授权的工作目录内操作—— 工作目录之外的文件夹它碰不到，系统目录它改不动，这是官方口径写明的。
但这不等于你可以随手把原件丢进去：放进工作目录 = 允许它读写。 所以规矩是两条—— 一、只在工作目录内操作；二、重要资料只放副本。 本课所有素材都要求存成 input/ 下的新文件，就是这个原因。

二、脏数据的六张面孔与清洗规则本课核心

票据变成表之后，问题才刚开始。报销清单是最容易脏的一类表—— 因为它是很多人、很多次、从很多张票上敲出来的。 脏数据不是「数据错了」，而是「数据长得不规矩」： 规矩一破，后面的求和就全跟着错，而且错得很隐蔽。

六张面孔与清洗后的写法均为教学示意，取自本课素材里真实存在的脏数据类型， 非某个具体文件的实测输出。

清洗指令的三要素，一条都不能少

很多人清洗只说一句「帮我清洗一下这张表」。这就等于让它替你做主—— 金额写中文的怎么转？重复票据号留哪条？它自己定，事后你对不上账， 而且财务问起来你答不出「这个数是怎么来的」。

要素要写清什么本课素材里的写法
数据源 哪个文件、哪些列、哪几行 input/报销清单.csv 的「票据号 / 开票日期 / 消费类型 / 金额 / 报销人 / 部门」六列
规则 每张面孔怎么处理，逐条点名 日期统一成 YYYY-MM-DD；金额去掉 ￥ 和千分位、中文转阿拉伯、统一 2 位小数； 消费类型归并到五类；完全相同的行删到只剩 1 条； 票据号相同但金额不同的保留并标【待核】
输出 新文件叫什么、放哪、原文件不许动 output/报销清单_清洗后.xlsx，禁止覆盖原文件
报销场景里最该写死的是「不许猜」 遇到它判不了的值（比如金额被遮、日期模糊、消费类型读不出）， 正确做法是标成【待核实】留给你判断， 而不是自己补一个看起来合理的数——那等于替你做了一笔你不知情的账。 更危险的是「票据号相同但金额不同」：这两条可能是同一张票录错了， 也可能是两张不同的票，只有人能判断，AI 不许自动删掉其中一条。 这两条规则要显式写进指令。

第 2 步 · 把下面这段指令复制发送 整句粘贴，不要自己改写—— 里面每一条规则都是对着上面这张表的具体问题写的。

请读取 input/报销清单.csv，按下面的规则清洗，输出到 output/报销清单_清洗后.xlsx。

清洗规则（逐条执行，不要自己加规则）：
1. 开票日期统一成 YYYY-MM-DD 格式（2026.9.1、2026/8/26、2026年9月18日、9/5 都要变成 2026-09-05 这种）；
   缺年份的按 2026 年补，并在报告里说明补了几处；
2. 金额列只保留数字：去掉 ￥ 和千分位逗号，中文数字转成阿拉伯数字
   （一百二 → 120.00，二百八 → 280.00，五百 → 500.00），统一保留 2 位小数；
3. 消费类型归并到这五类：交通、住宿、餐饮、办公用品、差旅。
   "出租车""打车""市内交通"归到"交通"，"工作餐"归到"餐饮"；
   出现这五类之外、或你判读不了的值，一律写【待核实】，不要自己归类；
4. 整行完全为空的行：删除，并在报告里写明删了几行；
5. 重复票据号分两种情况处理，不要混为一谈：
   a. 整行完全相同的记录，只保留 1 条，删掉多余的；
   b. 票据号相同但金额（或其他字段）不同的记录：两条都保留，不要删除任何一条，
      并在新增列"是否待核"里把这两条都标成【待核】；
6. 新增一列"是否待核"：除了上面 5b 的情况，读不清或判不了的值也标【待核】，其余写"正常"。

输出要求：
- 保存为 output/报销清单_清洗后.xlsx；
- 不要覆盖原文件 input/报销清单.csv；
- 清洗完成后，用文字告诉我：清洗前后各多少行、删了几个空行、
  删了几条完全重复行、日期改了几处、金额改了几处、消费类型改了几处、
  有几条被标成【待核】分别是哪几条。

三、汇总：口径你定，对账它做最容易吵起来的地方

数据洗干净了，接下来汇总。这里有个坑比脏数据更隐蔽： 同一批票据，换一种算账口径，报销总额能差出上千元。 而这些算法听起来都叫「报销总额」。

可运行演示 ② 同一个「报销总额」，三种口径能差 1740 元

数据取自本课 报销清单.csv 清洗后的 13 笔： 其中 2 笔是「同一票据号、金额不同」的待核票据（780.00 / 960.00）。

—口径 A：待核票据全部计入
—口径 B：待核票据只算先出现那条
—口径 C：待核票据全部剔除
数值由本页脚本按上面那 13 笔数据真实计算得出，非估算； 但这份数据本身是教学用虚构票据，非实测数值。

看到了吗？三个都是「报销总额」，没有一个算错，但结果差出 1740 元。 按 A 报上去，财务一核发现多算了；按 C 报上去，那两笔钱就没人认领了。 所以汇总之前第一件事不是发指令，是把口径定死。

要定的口径你必须回答的问题不定会怎样
待核票据怎么办 全额计入？只算先出现那条？还是全部剔除等核实后再报？ 三种算法差 1740 元，而且每一种都「算得没错」
按什么维度汇总 按部门？按月份？按消费类型？要不要一次给三张？ 只给部门的，财务要月份的，你得让它重跑一遍
精度与排序 金额保留几位小数？明细按开票日期升序还是按金额降序？ 交上去的表格式和财务要求不一致，被打回来
对不上怎么办 分组合计加不出总额时，是让它报出来，还是让它调平？ 它为了「凑上」悄悄改一个数，这是最坏的一种结果
你不用会写公式，但必须会说清楚算什么 各部门报销额 = 按部门汇总金额列 这句话你会说就行， 公式长什么样是它的事——你也可以直接让它 「用 SUMIF 写出各部门报销额的公式，并把结果算出来给我核」， 公式和结果一起拿到手。 但「算什么、按什么条件、对不上怎么办」这三句必须你说—— 它替你定的那部分，就是你事后不敢签字的那部分。

第 3 步 · 用一段脚本自己再对一遍账： 把下面这段存成 check_total.py，放在 wb-试验 目录下， 在 WorkBuddy 里让它运行（你也可以自己在本机命令行跑）。 这一步是让你拿到一个不依赖它口述的第三方数字。

# -*- coding: utf-8 -*-
"""
报销总额对账：明细逐笔加总  <->  按部门分组合计
依赖：  pip install openpyxl
运行前提：
  1. 本脚本放在 wb-试验 目录下，与 output/ 同级；
  2. 实操② 已经生成 output/报销清单_清洗后.xlsx；
  3. 该表第 4 列是"金额"、第 6 列是"部门"（第 1 行是表头）。
运行：  python check_total.py
"""
import openpyxl

SRC = "output/报销清单_清洗后.xlsx"

def to_float(v):
    """把金额格转成浮点数：顺手去掉可能的 ￥ 和千分位逗号。"""
    if v is None:
        return None
    s = str(v).replace("￥", "").replace("¥", "").replace(",", "").strip()
    try:
        return float(s)
    except ValueError:
        return None


wb = openpyxl.load_workbook(SRC)
ws = wb.active

# 1) 明细逐笔加总
detail, rows, bad = 0.0, 0, []
for r in ws.iter_rows(min_row=2, values_only=True):
    amt = to_float(r[3])
    if amt is None:
        continue          # 空行跳过，不计入笔数
    if str(r[3]).strip() and amt is None:
        bad.append(r[0])  # 有值却转不成数字 -> 记下来，不硬凑
    detail += amt
    rows += 1

# 2) 按部门分组合计
by_dept = {}
for r in ws.iter_rows(min_row=2, values_only=True):
    amt = to_float(r[3])
    if amt is None:
        continue
    dept = r[5] or "（部门为空）"
    by_dept[dept] = by_dept.get(dept, 0.0) + amt

group = sum(by_dept.values())

print("明细笔数：", rows)
print("明细逐笔合计：%.2f" % detail)
for d, v in by_dept.items():
    print("  %s：%.2f" % (d, v))
print("部门分组合计：%.2f" % group)
print("对账结果：", "对得上" if abs(detail - group) < 0.01 else "对不上，差 %.2f，报出来" % abs(detail - group))
if bad:
    print("金额转不成数字的票据号：", bad)

要做到这三条，就算做完了

  1. 脚本跑出来的明细合计是 10601.50，笔数是 13 和它给的总额完全一致。
    对不上：⚠️ 先让它把 13 笔逐笔列出来， 你按票据号和脚本的输出一条条对，看是漏了哪笔还是金额转错了。
  2. 部门分组合计也等于 10601.50 市场部 6680.00、技术部 3200.00、行政部 721.50，加起来正好 10601.50。
    对不上：⚠️ 说明有笔被归错部门或漏了—— 让它把每个部门分别有哪些票据号列出来，你数一遍。
  3. 月份和类型两组也都等于 10601.50 2026-08 是 1205.50、2026-09 是 9396.00； 交通 3526.00、住宿 1980.00、餐饮 1050.00、办公用品 2365.50、差旅 1680.00。
    对不上：⚠️ 别让它「调平」，让它把差额和明细列出来， 你来判断是哪一笔出了问题。

要交的成果：报销汇总.xlsx（三张分组表） + 它复述的口径原文 + 脚本跑出来的对账结果。

验收三道关：这三道只有你能把

到这一步，AI 已经把活干完了。剩下的事它一件都干不了： 它不知道这笔钱该不该报、票据是不是真的、超没超标。 验收不用全查，守住三道关就够了——这三道关 AI 自己判不了， 因为错的是它对任务的理解，不是它的算术。

关卡核什么不对说明出了什么事
① 行数 清洗后剩几笔，和你手上的票据数一不一样 删多了 = 它把不该删的当重复删了； 没删 = 去重规则没生效，总额虚高
② 口径 它复述的计算口径，逐字对比你写的那几条 对不上 = 指令里那句约束它没严格遵守，结果全废
③ 合计数 各分组加起来，等不等于明细逐笔的总额 对不上 = 统计过程中丢了数据或串了组； 它要是「调平」了，比不对还危险
一句话记住这一课 表格处理里，AI 负责快，你负责对。 它几分钟能干完你两小时的活，但「这批钱能不能报、这个数能不能交上去」这个判断， 永远只有签字那个人能做。

共 5 题单选 / 判断 · 点击按钮查看解析
1把一叠发票交给 AI，为什么不该一上来就让它算报销总额？
  • A. 因为它算得慢，先让它熟悉一下文件
  • B. 因为你不知道它读了几张票、看不清的金额它怎么处理，出来的数不敢报给财务
  • C. 因为它必须先安装 Excel 软件
  • D. 因为报销总额要财务审批
答案：B。先让它认字段、报家底，是为了确认你们看的是同一批票： 几张票、每个字段读成什么、哪几处读不清。 这些不先说清楚，它算出来的总额再快也不代表能报。 A 说反了——它恰恰算得很快，快才是风险。
2金额列里有个值是「¥1,280.00」，最可能导致什么问题？
  • A. 表格变宽，不好看
  • B. 文件打不开
  • C. 整列被当成文本，SUM 求和时静默跳过这一笔，总额少一截
  • D. 金额会自动四舍五入成整数
答案：C。带 ¥ 和千分位逗号的值在计算机眼里是文本， 不是数字。SUM 求和会把它跳过去——而且不会报错， 静默跳过比报错危险得多，你根本不知道少了这一笔。 这也是为什么本课把「金额只保留数字」单列成一条清洗规则。
3同一个票据号出现两条记录，金额分别是 780.00 和 960.00，正确做法是？
  • A. 让 AI 自动保留金额较大的那条，删掉另一条
  • B. 让 AI 自动取两条的平均数
  • C. 两条都保留、都标【待核】，交给人核对后再决定
  • D. 直接删掉两条，等下次重新录入
答案：C。「票据号相同但金额不同」有两种可能： 同一张票录错了，或者真的是两张票。 这个判断 AI 做不了，也不该做——A 和 B 都是让它替你决定一笔钱， D 更糟，直接把钱弄丢了。正确做法是两条都留着、都标【待核】， 你翻原始票据核完再定，并且把这个规则显式写进指令。
4判断：清洗报销清单时，把所有含空值的行删掉是最省事、也最推荐的做法。
  • A. 正确，空着的行本来就没用
  • B. 错误，删行会改变笔数和总额，缺哪个字段应该标记后按规则处理
答案：B（错误）。一张票只在开票日期上缺了一个值， 你把整行删了，等于把那笔钱一起扔掉—— 报销总额悄悄少了一笔，而且看不出来是本该有的还是录入错的。 正确做法是保留行、标记缺哪个字段、按你定的规则处理。 唯一该删的是整行完全为空的那种空行，并且要让它报出删了几行。
5判断：同一批票据，「待核票据全部计入」和「待核票据全部剔除」两个口径算出的报销总额，可能相差上千元。
  • A. 正确，两种口径差多少取决于待核票据有多少钱，差上千很常见
  • B. 错误，报销总额只有一种算法，不可能有差别
答案：A（正确）。用本课的素材实际算过：全部计入是 10601.50 元， 全部剔除是 8861.50 元，差 1740.00 元。 两种算法都没有算错，错的是没提前定口径。 这就是本课把「待核票据怎么办」列进口径表第一条的原因。

本课要点回顾

这一课要带走五件事

  1. 先认字段、报家底，再动手——票据号、开票日期、消费类型、 金额、报销人、部门，它认完你认可了才往下走； 读不清的标【待核实】，不许它编；
  2. 官方口径三条：数据本地执行不上传、沙箱隔离、 只访问授权目录（核对日期 2026-09-24）； 底线是只在工作目录内操作、重要资料只放副本；
  3. 清洗指令三要素：数据源 + 规则 + 输出， 规则要逐条点名：日期统一、金额转纯数字、类型归并、 空行删除、重复票据号分两情况处理；
  4. 汇总之前先把口径定死：待核票据怎么办、按什么维度汇总、 保留几位小数、对不上不许调平—— 同一个「报销总额」能差 1740 元；
  5. 验收三道关：核行数、核口径、核合计数， 再加上一节人工核对清单—— 这三道 AI 自己判不了，只能你来。

课后作业单选 / 多选 / 判断

下面这套题发在学习通上。点一下展开，再点框内右上角「复制」就能整段拿走。

1.（单选）把一份含发票金额、报销人的 Excel 交给 WorkBuddy 处理，按官方口径，数据在哪里执行？
A. 上传到云端服务器处理
B. 在用户本地环境执行处理，不上传
C. 由用户手动复制到网页里处理
D. 先传给模型厂商，算完再取回结果
【答案】B
【解析】官方「常见问题·数据安全说明」原文：数据本地执行不上传，所有数据在用户本地环境执行处理；服务端仅处理数据片段，用后即弃，不保存、不用于模型训练。A、D 与官方口径相反，C 不是它的工作方式。

2.（单选）一条完整的表格处理指令，应该包含哪三个要素？
A. 文件名 + 图表类型 + 字体
B. 数据源 + 处理规则 + 输出形式
C. 模型 + 运行模式 + 积分余额
D. 行数 + 列数 + 文件大小
【答案】B
【解析】数据源（哪个文件、哪些字段）+ 规则（怎么清洗、算什么）+ 输出（新文件叫什么、放哪、原文件不许动）。少了规则，AI 就会替你做主——比如把看不清的金额自己猜一个数填进去。A 混进了格式细节，C 是环境配置，D 是摸底结果而不是指令。

3.（多选）下面哪些属于本课说的报销清单里的「脏数据」？
A. 同一个票据号出现了两次，金额分别是 780.00 和 960.00
B. 金额列里出现"一百二"这样的中文数字
C. 开票日期列同时存在 2026.9.1 和 2026/8/26 两种写法
D. 金额是 1280.00
【答案】ABC
【解析】A 是重复票据号、B 是金额格式不统一、C 是日期格式不统一，这三种都会让求和与汇总结果失真。D 是规范的数字金额，不是脏数据——不要把「看着不顺眼」当成脏数据，清洗必须按明确规则来，不能凭感觉。

4.（单选）让 AI 算报销总额之前，最重要的一个动作是？
A. 让它自己判断该怎么算，它比我们懂
B. 先把口径定死：待核票据怎么办、按什么维度汇总、保留几位小数、对不上怎么办
C. 让它多算几遍，取几次结果的平均
D. 让它同时给出三种结果，到时候再挑一个
【答案】B
【解析】口径不定，AI 就会替你做主。同一批票据，「待核票据全部计入」和「待核票据全部剔除」能差出 1740 元，两种都没算错。D 看似稳妥，其实把决策又推回给你，而且三个结果你不知道哪个是对的；C 更没有意义，重复算同一个错误口径只会得到同一个错误答案。

5.（判断）清洗数据时，让 AI 直接覆盖原文件更省事，是推荐做法。
A. 正确，省一个文件，磁盘也干净
B. 错误，应输出为新文件，原文件保留以便回溯
【答案】B（错误）
【解析】原文件是唯一能证明「改之前是什么样」的证据。清洗规则一旦定错，覆盖之后既没法对比也没法回退。指令里要写明输出的新文件名，并加上「不要覆盖原文件」这句——本课四个实操都写了。

6.（多选）AI 给出报销汇总结果之后，下面哪几项必须由人来核？
A. 清洗后的笔数与手上的票据数是否一致
B. 它实际采用的计算口径是不是你定的那条
C. 各部门、各月份的金额合计加起来是否等于明细逐笔的总额
D. 它生成的图表颜色好不好看
【答案】ABC
【解析】这三关 AI 自己判不了：笔数不对说明去重或删行越界；口径不对说明指令里的约束没被严格遵守；合计数对不上说明统计过程中丢了数据或串了组。D 是观感问题，不影响数据是否可用。另外票据真伪、是否超标、标着【待核实】的字段，也都只能人工核。
